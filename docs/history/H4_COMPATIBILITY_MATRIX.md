## What a cell certifies

`PASS` means the suite ran on that (JDK, SDK) pair and produced the **same set
of `classname#method` ids** as the reference cell, with zero failures, zero errors
and zero skips. Comparing counts would let a swapped suite pass.

## Coverage limits, stated rather than implied

- **Policy content combinations are not enumerated.** "Policy" here is the policy
  surface of this codebase, not every policy an author could write.
- **A cell is not host evidence.** B6.7 runs the installed-plugin UAT against the
  declared SDK only; a cell here does NOT show the plugin loading in a live
  PipelineK host on that SDK.
- **A cell is an observation, not a support promise.**
- **The Gradle launcher is pinned to JDK 21 in every cell.** The JDK axis is
  the *test toolchain* (`jvmToolchain` via `-PtestJvm`), not the JVM running
  Gradle. This is a real limit, observed: launching this build on the ambient
  JDK `25.0.4.1` fails at configuration time with `IllegalArgumentException: 25.0.4.1`
  from the Kotlin compiler plugin, before any task runs. That failure is
  independent of these changes and reproduces on a pristine tree.
  So a cell is evidence that the plugin *compiles and tests* under that JDK,
  not that the whole toolchain bootstraps on it.
